# M1 registry implementation boundary

The registry stores immutable scoped descriptors, adapter manifests, observation
specifications, safety envelopes and embodied verification specifications. A
registration atomically records its original writer JSON, one domain event and
the original idempotent response. No registered declaration grants a capability.

Existing project, principal and workspace identities remain authoritative. The
focused stores compose the existing MemoryStore/PostgresStore; migration
[0021](../../../migrations/versions/0021_v05_robotics_registry.py) follows
`0019_v04_m8_activation` and adds five tables. A trusted deployment bootstrap
explicitly binds a legacy project to one workspace. An ordinary registration
cannot create or change that binding. Writers require active human
OWNER/ADMIN/DEVELOPER membership; every read checks current membership and scope.
PostgreSQL holds identity/membership row locks during mutation, and serializes
each project's registry writes. Artifact verification happens outside that
transaction, followed by a fresh authorization check before commit.

Robotics references resolve to the exact scoped original writer and indexed
identity. Compatible minor writer payloads remain intact, while dependency use
requires a fully understood version. M1 rejects unresolved optional objective
references; frozen experiments and their run binding belong to M4. Policy,
verifier-implementation and general artifact references remain declarations
until their respective admission services validate them. Adapter artifact
registration additionally requires an injected trusted byte/signature verifier;
the absent implementation fails closed.

Conformance completion is an internal host-result hook with an injected trusted
attestation verifier and an active independent SERVICE principal/member. An
ordinary caller cannot register a conformance PASS. The hook checks the original
report, producer, exact suite/verifier identity and full dependency closure,
then atomically appends the report, association, revision and event. A read
returns PENDING unless it receives the exact current closure and current trust
still covers the newest result for it. Report summaries are bounded to 100 per
read; the current closure is looked up separately so an older qualifying
profile is not lost behind that limit. Qualification grants no action authority.
The live runner, evaluator and artifact-signature trust provisioning remain
unavailable until their separate host integration is implemented.

Under the coordinator's explicit 9 September M1 decision, the unreleased v0.5
event contract adds `simulation_contract.registered` for the supporting registry
types. All existing event literals retain their meanings. Only its affected
generated schema and a separate synthetic registry-event fixture change; M0
commits, evidence snapshots, imported frozen packages and v0.4 schemas remain
preserved. The fixture is not runtime evidence.

Focused witnesses cover Memory/PostgreSQL parity, raw writer seals, immutable
slots, current authorization, cross-scope refusals, races and rollback, exact
conformance joins, revocation, bounded pagination and corrupt original/indexed
records. A separate PostgreSQL DDL test runs down/up inside a transaction and
rolls back to restore previous test rows. These are engineering tests; all
composite AC5 obligations and actual simulator conformance remain pending.
